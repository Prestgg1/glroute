# glroute

Lightweight LLM router for Gleam — priority fallback with BEAM concurrent request handling over `gdantic_ai`.

All code, tests, and documentation were generated by AI and reviewed by me.

Built on [`gdantic_ai`](https://github.com/Prestgg1/gdantic_ai) — PydanticAI-inspired typed agent library for Gleam. While [OmniRoute](https://github.com/diegosouzapw/OmniRoute) is a sequential fallback proxy that does **not** support parallel requests, `glroute` provides a **custom OpenAI-compatible address** that handles **parallel incoming requests concurrently via BEAM** — each HTTP request runs in its own Erlang process.

```sh
gleam add glroute
```

## Why glroute?

[OmniRoute](https://github.com/diegosouzapw/OmniRoute) (`v3.8.49`) is a powerful unified AI gateway — 290 providers, 19 combo strategies — but its routing is **sequential** and it **does not support parallel requests**: `for (orderedTargets) await executeTarget()` — one request at a time per route, no concurrent handling of many clients.

`glroute` fixes this:

- **`Priority` (sequential fallback per request)** — like OmniRoute combos: try agents in order, return the first success. Simple, reliable. `List(Agent(deps, output))` API.
- **Parallel incoming requests** — the server exposes a custom OpenAI-compatible address (e.g., `http://localhost:3000/v1`) and handles **multiple parallel requests concurrently** via BEAM/Erlang — each request in its own lightweight process, no blocking. This is BEAM's strength, not a routing strategy.
- **Production-ready, small** — `mist` HTTP server, typed output via `glon`, mockable, ready to harden later.

## Features

- **Priority routing** — sequential fallback per request (`List(Agent)`)
- **Parallel request handling** — concurrent via `mist` + BEAM scheduler (each `POST /v1/chat/completions` in its own process)
- **Custom OpenAI-compatible address** — clients set `base_url = "http://localhost:3000/v1"` and use standard OpenAI SDKs
- **Typed** — `Agent(deps, output)` + `glon.JsonSchema(output)` — schema + decoder stay in sync
- **Any provider** — reuses `gdantic_ai` providers: `OpenAI`, `Gemini`, `OpenAICompatible` (Ollama, OpenRouter, Together, Groq, Azure...)
- **Tested** — priority + server concurrency tests with mocked HTTP

## Quick Start

### 1. Define agents with priority

```gleam
import gdantic_ai/agent
import gdantic_ai/provider
import glon
import glroute

pub type City { City(city: String, country: String) }

let schema = {
  use city <- glon.field("city", glon.string())
  use country <- glon.field("country", glon.string())
  glon.success(City(city:, country:))
}

let agents = [
  agent.new(provider.openai("gpt-4o", "sk-...")) |> agent.with_glon(schema),
  agent.new(provider.gemini("gemini-2.5-flash", "AIza...")) |> agent.with_glon(schema),
  agent.new(provider.openai_compatible("llama3", "http://localhost:11434/v1", "ollama"))
    |> agent.with_glon(schema),
]
```

### 2. Direct routing (without server)

For library use — sequential fallback per call:

```gleam
// Tries a1 → a2 → a3, returns first Ok
case glroute.route_priority(agents, "Which country is Paris in?", Nil) {
  Ok(result) -> echo result.output  // City("Paris", "France")
  Error(e) -> echo e
}
```

Multiple callers can run `route_priority` concurrently via `process.spawn` — BEAM handles parallelism.

### 3. Server with custom OpenAI-compatible address (recommended)

For production — start a server that clients can point to:

```gleam
import glroute
import gleam/erlang/process

pub fn main() {
  // String-output agents for OpenAI-compatible server
  let agents = [
    agent.new(provider.openai("gpt-4o", "sk-...")),
    agent.new(provider.openai("gpt-4o-mini", "sk-...")),
  ]

  let assert Ok(_) = glroute.serve(agents, 3000)
  // Now available at:
  //   POST http://localhost:3000/v1/chat/completions
  //   GET  http://localhost:3000/v1/models
  //   GET  http://localhost:3000/health
  //
  // Clients set: base_url = "http://localhost:3000/v1"
  // e.g., OpenAI SDK: new OpenAI({ baseURL: "http://localhost:3000/v1", apiKey: "sk-..." })
  //
  // Parallel requests from many clients are handled concurrently —
  // each in its own BEAM process (mist), no extra code needed.

  process.sleep_forever()
}
```

**Parallel test:** 10 clients `POST` at the same time → all handled concurrently, each with priority fallback internally.

## Architecture

```
glroute/
├── src/glroute/
│   ├── route.gleam      # agent_model_name helper
│   ├── parallel.gleam   # route_priority (sequential fallback loop)
│   └── server.gleam     # mist HTTP server — OpenAI-compatible, BEAM concurrent
├── src/glroute.gleam    # Public API: route_priority, serve, serve_with_config
└── uses gdantic_ai/
    ├── provider.gleam   # OpenAI / Gemini / OpenAICompatible
    ├── agent.gleam      # Agent(deps, output) + with_glon + run
    └── http.gleam       # Mockable HttpClient
```

```
Client A ──POST /v1/chat/completions──┐
Client B ──POST /v1/chat/completions──┼─► mist (BEAM) ─► each in own process ─► route_priority(agents) ─► provider
Client C ──POST /v1/chat/completions──┘         \ parallel incoming requests handled concurrently
```

Per-request routing: `agent1 ──fail──► agent2 ──ok──► return` (priority, sequential).

Server parallelism: BEAM scheduler, no shared state, production-ready.

## API

```gleam
// Priority: List(Agent) -> Result(RunResult, GdanticError) — sequential fallback
pub fn route_priority(
  agents: List(Agent(deps, output)),
  prompt: String,
  deps: deps,
) -> Result(RunResult(output), GdanticError)

// Server: custom OpenAI-compatible address with parallel handling
pub fn serve(
  agents: List(Agent(Nil, String)),
  port: Int,
) -> Result(Nil, String)

pub fn serve_with_config(
  agents: List(Agent(Nil, String)),
  config: ServerConfig,
) -> Result(Nil, String)

pub type ServerConfig { ServerConfig(port: Int, host: String) }
```

Endpoints exposed by `serve`:

- `POST /v1/chat/completions` — OpenAI-compatible, `{"model", "messages": [{"role","content"}]}` → priority fallback → `{"choices": [{"message": {"content"}}]}`
- `GET /v1/models` — list of configured models
- `GET /health` → `{"status":"ok"}`

## Comparison

| Feature | OmniRoute | glroute |
|---|---|---|
| Routing per request | Sequential fallback (1-at-a-time) | **Priority** sequential fallback |
| Parallel requests | **Not supported** | **Yes** — via BEAM, each HTTP request in own process |
| Custom address | `http://localhost:20128/v1` | `http://localhost:3000/v1` (configurable) |
| Language | Node.js | Gleam (Erlang/OTP) |
| Scope | 290 providers, gateway, compression | Small, focused, production-usable router |
| Typed output | No (JS) | Yes (`glon` schema + decoder) |
